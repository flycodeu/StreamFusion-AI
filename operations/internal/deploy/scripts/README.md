# 目标服务器命令维护

软件商城的可发布安装步骤在 `internal/serviceinstall/templates/`，通过平台“命令模板”编辑、发布。此目录维护执行器使用的账号操作、安装适配、配置文件和验证命令。

| 目录 | 维护内容 |
| --- | --- |
| `native/` | 源码编译、MySQL 初始化、服务账号、systemd 单元和程序包装脚本 |
| `docker/` | Docker 配置及容器内服务配置 |
| `config/` | MediaMTX、ZLM、SeaweedFS 配置 |
| `git/` | Git 账号、SSH 密钥、认证及终端配置 |
| `node/` | Node 终端加载、npm 镜像配置及检查 |
| `verify/` | 软件版本、扩展、配置和健康验证命令 |
| `observe/` | 软件发现和配置读取脚本 |
| `commands.json` | 容器生命周期、账号授权、Node 操作及 Docker 参数片段 |

各子目录的 `commands.json` 自动合并；命令名称必须唯一。每个 JSON 数组保存完整 argv 或明确的 argv 片段，`$1`、`$2` 表示独立参数，`${1}` 可放在单个参数内部，`$*` 展开传入的参数数组。参数直接传给原执行入口，不经过 Shell 解释。

`.sh`、`.js`、`.py` 和配置文件保存原始内容；`.tmpl` 使用原调用点对应的占位符。Go `fmt` 模板中的字面百分号写作 `%%`。不要统一裁剪文件首尾空白：部分片段有意不带尾换行。

修改后重新构建执行器，并运行 `go test -buildvcs=false ./...`。执行器继续负责参数校验、权限隔离、目录归属、超时、日志脱敏和结果核验；此目录不改变授权范围。已提交任务使用提交时的命令快照。
